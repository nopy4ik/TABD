## 3. Как обучается модель

Файл обучения TFT: [`scripts/train_tft.py`](/data/ssa/TABD/scripts/train_tft.py)

### Пошагово

1. Загружается `5stations_data.csv`.
2. Данные сортируются по станции и времени.
3. Для TFT создается `time_idx`.
4. Признаки приводятся к нужным типам:
   - категориальные - в строки;
   - числовые - в `float`.
5. Данные делятся по времени:
   - train - исторический период;
   - validation/backtest - декабрь 2023 года.
6. Для топлива и товаров строятся отдельные конфигурации.
7. Модель обучается через `pytorch-forecasting` и `lightning`.
8. Сохраняются:
   - checkpoint;
   - метрики;
   - прогноз backtest;
   - будущий сценарный прогноз.

### Почему две отдельные модели

- для топлива ряд более стабильный;
- для магазина ряд разреженный и содержит много нулей;
- отдельная настройка помогает не смешивать разные типы поведения спроса.

### Почему магазин обучается хуже

Основные причины:

- очень много нулевых значений;
- спрос по товарам скачет сильнее, чем по топливу;
- будущие погодные и рекламные признаки для прогноза задаются сценарно, а не известны точно;
- на небольшом датасете сложной модели труднее обогнать простую.

## 4. Что делает dashboard

Файл дашборда: [`app/app.py`](/data/ssa/TABD/app/app.py)

### Что показывает верхняя панель

- выбранную АЗС;
- период данных;
- статус модели.

### Вкладка «Аналитика»

Показывает:

- динамику продаж топлива и выручки магазина;
- структуру продаж топлива по видам;
- структуру выручки магазина по категориям;
- влияние погоды и акций.

### Вкладка «Прогноз»

Показывает:

- факт против прогноза по топливу;
- факт против прогноза по товарам;
- будущий сценарный прогноз на 7 дней;
- график ошибок прогноза.

### Вкладка «Качество и признаки»

Показывает:

- MAE;
- MSE;
- RMSE;
- R2;
- графики поведения трафика и ошибок.

### Вкладка «Рекомендации»

Показывает:

- краткий вывод по выбранной АЗС;
- таблицу по всем станциям.

## 5. Как объяснять код преподавателю

Можно отвечать так:

1. Сначала я беру исходный CSV с 5 АЗС.
2. Потом делю признаки на статические, временные, погодные, трафиковые и маркетинговые.
3. Для прогнозирования топлива и товаров обучаю отдельные модели.
4. Для TFT задаю отдельные конфигурации для топлива и магазина.
5. После обучения сохраняю метрики и прогнозы в `artifacts/`.
6. Dashboard читает эти артефакты и визуализирует результат.

## 6. Короткий вывод

- Данные в проекте реалистичные и многомерные.
- Топливо моделируется стабильнее, чем товары.
- Магазин хуже из-за большого числа нулей и более шумного спроса.
- Dashboard собран так, чтобы показать весь цикл: данные -> обучение -> прогноз -> оценка -> выводы.
