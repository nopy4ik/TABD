# Отчет по лабораторной работе

## Тема

TFT-анализ сети АЗС и построение интерактивного dashboard на Dash.

## Цель работы

Провести анализ почасовых данных сети АЗС, обучить модель Temporal Fusion Transformer для прогнозирования продаж, сохранить обученную модель и представить результаты в интерактивном dashboard.

## Ход работы

### 1. Изучение задания

Изучена формулировка задания из `_задание/Задание.docx`. По заданию необходимо провести TFT-анализ сети АЗС, обучить модель, сохранить ее для повторного использования, построить прогнозы продаж топлива и сопутствующих товаров, сформировать рекомендации и объединить результаты в dashboard.

### 2. Изучение данных

Изучено описание переменных из `_задание/описание данных.docx`. В проекте используются два основных CSV-файла:

- `_задание/detailed_data.csv` - почасовые данные по продажам, трафику, погоде, акциям, рекламе, ценам и календарным признакам.
- `_задание/stations_metadata.csv` - статические характеристики АЗС.

Исходные данные решено не изменять. Все новые признаки, агрегаты, прогнозы, метрики и графики будут сохраняться отдельно в `artifacts/`.

### 3. Выбор инструмента визуализации

Вместо Power BI выбран Python-фреймворк Dash. Это позволяет собрать dashboard в одном Python-проекте и напрямую использовать результаты обучения модели, прогнозы, метрики и рекомендации.

### 4. План моделирования

Основная целевая переменная первой версии модели - `total_fuel_sales`. Дополнительно планируется обучить или расширить прогнозирование для продаж топлива по типам и `shop_total_revenue`.

Для оценки качества модели будут использоваться метрики `MAE`, `MSE`, `RMSE`, `R2`. Для отчетности также будут построены графики actual vs forecast, ошибки прогноза и важность признаков.

### 5. Подготовка структуры проекта

Проект переведен с Power BI на Dash. Удалены старые Power BI-материалы и сгенерированные `derived`-витрины, так как они были сделаны под другой сценарий. Исходные файлы задания в `_задание/` не изменялись.

Добавлены рабочие каталоги:

- `app/` - Dash-приложение;
- `artifacts/` - прогнозы, метрики, рекомендации и будущие веса модели;
- `reports/` - отчет по лабораторной;
- `scripts/` - скрипты обучения и подготовки артефактов.

### 6. Baseline-модель

Для проверки полного пайплайна до TFT обучена baseline-модель `HistGradientBoostingRegressor` по целевой переменной `total_fuel_sales`.

Разделение данных выполнено по времени:

- train: данные до 2023-12-01;
- test: декабрь 2023 года.

Полученные метрики на тестовом периоде:

- `MAE`: 4.4205;
- `MSE`: 94.1926;
- `RMSE`: 9.7053;
- `R2`: 0.9767.

Сохранены артефакты:

- `artifacts/forecasts/baseline_forecast.csv`;
- `artifacts/metrics/baseline_metrics.json`;
- `artifacts/metrics/baseline_feature_importance.csv`;
- `artifacts/recommendations/station_recommendations.csv`.

### 7. Первая версия dashboard

Создано Dash-приложение `app/app.py`. Оно показывает:

- динамику продаж топлива и выручки магазина;
- средние продажи и трафик по часам;
- actual vs forecast на тестовом периоде;
- top-20 признаков baseline-модели;
- рекомендации по выбранной АЗС.

Приложение запускается командой:

```bash
python app/app.py
```

После запуска dashboard доступен по адресу `http://127.0.0.1:8050/`.

### 8. Текущий блокер TFT

Установлены `pytorch-forecasting`, `lightning`, `dash` и `plotly`. Dash работает. PyTorch импортируется как CPU-версия. При проверке TFT-стека `lightning` падает на импорте из-за конфликта с локальным пакетом `transformers`: `ImportError: cannot import name 'AutoModel' from 'transformers'`.

Для обучения настоящей TFT нужно починить окружение: переустановить или удалить конфликтующий `transformers`, затем повторно проверить импорт `lightning` и `pytorch_forecasting`.
